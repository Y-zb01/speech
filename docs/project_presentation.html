📐 技术选型与算法详解

沿数据流顺序 — 原始音频 → Mel 特征 → VAD → TTS → MOS — 逐段说明每个环节的技术选型理由、算法原理和参数选择依据。

一、原始音频数据处理

目标
将任意格式的输入音频统一转换为 24000Hz / 单声道 / PCM16 WAV，为后续 Mel 特征提取提供一致的输入规格。

1.1 格式转换 (01_convert_audio.py)

技术选型

  • librosa.load() — 自动处理 mp3/m4a/flac/wav 等多格式解码，底层调用 audioread / FFmpeg
  • soundfile.write() — 输出标准 PCM16 WAV，底层基于 libsndfile，比 scipy.io.wavfile 更稳定且支持更多格式
  • 选择 24000Hz 而非 22050/16000 的理由：语音合成主流模型（HiFi-GAN、VITS、FastSpeech 2）的标准采样率，兼顾音质与计算效率。22050 是旧标准，16000 丢失高频细节（摩擦音 /s/ /f/ 能量可达 8-10kHz），44100 翻倍计算开销但语音频宽有限收益极低
  • 单声道而非立体声：语音场景无空间信息需求，单声道减少一半数据量，且所有 TTS 模型均以单声道训练

关键参数一览

采样率24000 Hz语音合成事实标准
声道1 (mono)无空间信息需求
位深PCM_1616-bit 有符号整数
最短1.0s过滤过短无效片段
最长15.0s适配模型最大输入
数据源LibriSpeech dev-clean10条 4位说话人

1.2 文本清洗 (02_clean_text.py)

处理流程

  1. 正则 \s+ 归一化多个空白字符为单个空格
  2. 首尾空白去除（str.strip()）
  3. Unicode 智能引号规范化（"smart quotes" → ASCII）
  4. 大写保留 — LibriSpeech 为英文，大小写提供额外语言学信息

设计考量

  • 不清除标点 — 标点是韵律建模的重要特征，TTS 依赖标点判断停顿和语调
  • 不转小写 — 大写字母对专有名词和句首识别有意义
  • 友好降级 — transcript 缺失时打印提示而非崩溃，支持无文本场景

1.3 时长统计 (03_duration_stat.py)

方法

  • soundfile 读取帧数 ÷ 采样率 = 精确时长（秒），比 librosa.get_duration() 更快且不重新解码
  • 生成 duration_report.csv 供数据质量审查
  • matplotlib 直方图展示时长分布均匀性，验证数据是否符合训练要求

1.4 元数据生成 (05_generate_metadata.py)

遍历 wavs/ 目录下所有 .wav 文件，与 transcript.txt 按文件名前缀匹配，生成包含 id / audio_path / duration_seconds / text 四列的 metadata.csv。 metadata.csv 是 TTS 模型训练的标准数据索引格式（借鉴 LJSpeech 和 LibriTTS 的数据组织方式）。

二、Mel 特征提取

目标
将时域音频波形转换为 Mel 尺度频谱图，作为语音合成和语音识别模型的标准输入声学特征。Mel 尺度模拟人耳对频率的非线性感知 — 人耳对低频变化敏感、对高频变化迟钝。

2.1 算法原理：STFT → Mel 滤波器组 → 对数压缩

Step 1: STFT 短时傅里叶变换

  1. 音频被切分为重叠的时间帧（帧长 1024 samples ≈ 42.7ms @24kHz）
  2. 每帧乘以 Hann 窗（平滑边缘，减少频谱泄漏）
  3. 每帧计算 1024 点 FFT，得到复数频谱
  4. 取幅值（magnitude）→ 平方得功率谱 → 仅保留 DC 到 Nyquist 的 513 个非冗余频率 bin

Step 2 & 3: Mel 映射 + 对数压缩

  1. 频率轴从线性 Hz 映射到 Mel 尺度：mel = 2595 × log₁₀(1 + f/700)
  2. 80 个等间距三角滤波器覆盖 0~12000Hz Mel 范围
  3. 低频区域滤波器密集（模拟人耳高分辨率），高频区域稀疏（模拟人耳低分辨率）
  4. 功率谱取对数（dB 尺度）：log(mel_power + 1e-6)，压缩动态范围，模拟人耳响度感知的对数特性

2.2 参数选择依据（每一个参数的选型理由）

参数取值选型理由
sample_rate 24000 Hz 与预处理阶段保持一致。语音频宽~8kHz（奈奎斯特定理需 ≥16kHz）。24000 可恢复 ≤12000Hz 信号，完全覆盖语音信息频带（包括摩擦音/s//f/的8-10kHz能量）。HiFi-GAN、VITS、FastSpeech 2 均以此为标准训练
n_fft 1024 @24kHz，帧长 1024 samples ≈ 42.7ms。频率分辨率 ≈ 23.4Hz/bin。平衡时间分辨率与频率分辨率的工程最优值 — 更大（2048）频率分辨率更好但时间精度下降，更小（512）时间精度高但谐波结构模糊
hop_length 256 帧移 ≈ 10.7ms，75% 帧重叠。10ms 级别是语音处理的黄金标准 — 音素最短持续约 30ms，10ms 帧移保证每个音素至少被 3 帧捕获。256 为 2 的幂，利于 GPU 内存对齐。典型 TTS 模型均使用此值
win_length 1024 与 n_fft 一致，无零填充。Hann 窗函数确保首尾平滑为零，避免帧边界的不连续引入伪影（Gibbs 现象）。零填充会引入虚假频率成分，不推荐
n_mels 80 语音合成领域事实标准 — Tacotron 2 (2018)、FastSpeech (2019)、FastSpeech 2 (2020)、VITS (2021)、HiFi-GAN (2020) 全部使用 80 维 Mel 作为输入/输出。128 维计算开销增加 60% 但信息增益极小（80 维已足够表示语音全部声学信息）；40 维丢失共振峰细节
fmin 0 Hz 包含基频 F0 信息（语音基频约 80-300Hz）。F0 是韵律模型的核心特征，决定语调高低和重音位置。不使用常见的高通截止（如 80Hz）以避免丢失低频韵律信息
fmax 12000 Hz Nyquist 上限（24000/2），覆盖语音全部频带。英语摩擦音 /s/ 能量可达 8-10kHz，/f/ 可达 6-8kHz，12000Hz 保留完整信息。再高（如 16000）需更高采样率且对语音无额外价值
输出格式 .npy NumPy 原生二进制格式，零序列化开销，支持内存映射（mmap）。单文件 = (80, frames) float32 矩阵，典型大小 ~100KB/样本，便于批量加载和 PyTorch DataLoader 直接读取

2.3 Mel 频谱解读

以 docs/mel_example.png 为例：横轴为时间帧（每帧 10.7ms），纵轴为 80 个 Mel 频率通道（0→12000Hz 由底→顶），颜色亮度代表对数能量（dB）。 可观测到清晰的谐波结构（水平亮纹，对应基频 F0 及其谐波）和共振峰轨迹（频率随时间变化的包络，这是区分不同元音 (/a/ /i/ /u/) 和浊辅音的核心声学线索）。

三、VAD 语音活动检测

目标
从长音频（160s）中自动检测并切分出人声片段，过滤静音和噪声区间，为后续 TTS 模型训练或评测提供干净的短语音片段。

3.1 算法选型：能量 VAD vs 深度学习 VAD

为什么用能量 VAD（而非 Silero / WebRTC）

  • 零依赖 — 不需要 PyTorch（Silero-VAD）或 C++ 工具链（WebRTC），纯 Python + NumPy 即可
  • 完全可解释 — 每一步（阈值、平滑、合并）都有明确的物理含义，调试方便
  • 参数透明可控 — 不像深度学习 VAD 那样是"黑盒"，所有阈值都可按场景调整
  • 录音棚/安静环境足够 — LibriSpeech 为录音棚录制、用户自录为安静室内，信噪比高，能量 VAD 精度与深度学习 VAD 差距极小
  • 实际验证：160s 长音频 → 50 段（1.0~4.6s），无噪音碎片，无误检静音段

对比：何时升级到 Silero-VAD

场景能量 VADSilero-VAD
录音棚✓ 优秀✓ 优秀
安静室内✓ 良好✓ 优秀
街道噪声△ 一般✓ 良好
多人交谈✗ 较差✓ 良好

噪声场景建议升级为 Silero-VAD 并做对比实验

3.2 五阶段能量 VAD 算法（06_vad_segment.py 217行）

阶段 1: 分帧 + RMS 能量计算

  • 帧长 25ms，帧移 12.5ms（50% 重叠）
  • 每帧计算 RMS 能量：√(mean(x²))
  • 设计理由：25ms 短期平稳假设 — 语音信号在 ~25ms 内近似平稳（声带振动状态不变）；12.5ms 帧移提供足够的边界定位精度

阶段 2: 自适应阈值

  • 能量归一化到 [0, 1]（消除录音增益差异）
  • 阈值 = mean(E) × 0.3 + median(E) × 0.35
  • 设计理由：均值对高能量异常值敏感（突然的咳嗽/撞击加分）；中位数对异常值鲁棒但可能低估语音；加权组合平衡两者。0.3/0.35 系数经网格搜索确定

阶段 3: 中值滤波

  • 窗口 3 帧（≈ 37.5ms），scipy.ndimage.median_filter
  • 消除孤立误检：连续 ≤1 帧语音 → 噪声；连续 ≤1 帧静音 → 保留
  • 设计理由：语音起止是连续过程（不会在 37.5ms 内反复出现/消失），中值滤波比均值滤波更保留边界的锐利度（不会模糊起止时刻）

阶段 4: 相邻段合并

  • 间隔 < 0.3s 的相邻语音段自动合并为一段
  • 设计理由：正常语速下句间停顿 ≥ 0.5-1.0s；0.3s 以下的间隔通常是句中短暂的闭音/塞音间隔（如 "boat" 的 /t/ 闭音 ~0.1-0.2s），不应切断

阶段 5: 时长过滤

  • < 1.0s → 丢弃（单音节、噪声、呼气声，无训练价值）
  • > 15.0s → 以 15s 为步长截断（超过模型训练最大输入，多句粘连需断开）
  • 1.0~15.0s → 直接保留

3.3 降噪后处理 (07_denoise.py 69行)

频谱减法原理

  • noisereduce 库：估计静音/噪声段的平均频谱，从整段音频频谱中减去该噪声分量
  • prop_decrease=0.85：每帧仅减去 85% 的估计噪声（而非 100%），避免过度减法导致音乐噪声（musical noise）伪影
  • stationary=False：非稳态模式，允许噪声频谱随时间变化（真实录音中的环境噪声不是恒定的）
  • 降噪在 VAD 切分之后逐段处理，避免对整条长音频（160s）做全量降噪导致内存溢出

四、TTS 文本转语音推理

目标

4.1 技术选型：Edge-TTS 的选型逻辑

为什么 Edge-TTS（而非 GPT-SoVITS/CosyVoice）

  • 零部署成本：pip install 即用，无需下载模型权重（CosyVoice ~2GB）、无需 CUDA 环境、无需复杂依赖
  • 中文质量高：Microsoft 神经网络 TTS 经过大规模训练，自然度和韵律媲美真人
  • 免费无 API 限制：通过 Edge 浏览器引擎接口调用，无需 Azure 订阅和配额
  • MVP 优先策略：先跑通全流程证明链路可行，后续替换开源模型做对比实验

4.2 推理工程实现 (tts_infer.py 101行)

容错设计

  • 3 次自动重试：网络波动或 API 短暂不可用时，2s/4s 指数退避重试
  • 0.5s 请求间隔：防止 API 限流触发 Microsoft 反爬机制
  • 异步批量执行：asyncio + edge_tts.Communicate，20 条在 ~25s 内全部完成
  • 推理日志：每条记录保存 id、模型、音色、文本、生成路径、耗时，完整可追溯

Windows 端执行原因

  • 双机协同架构中 "推理/训练" 职责归属 Windows 端，保持架构一致性
  • 后续替换为 GPT-SoVITS / CosyVoice 等 GPU 模型时，Windows 端无需改造直接承接

五、MOS 主观听音评测

目标
对合成语音进行双维度主观质量评分，量化语音合成的自然度和音色相似度，识别并分类 Bad Case 问题类型。

5.1 评测方法论与维度设计

双维度 MOS 设计

  • 自然度 MOS（1-5，0.5 步进）：
    评估语音是否流畅自然、有无机械感，不与参考音频比较，是独立听感的绝对评分。参考 ITU-T P.800 主观评测标准
  • 音色相似度 MOS（1-5，0.5 步进）：
    评估同一音色的不同合成样本之间音色是否稳定一致，检测音色漂移问题。Edge-TTS 场景下主要检测跨句稳定性
  • 0.5 步进（9 级量表）：比标准 5 级 MOS 更精细，可捕捉细微质量差异（如 3.5 vs 4.0 的差别）

Bad Case 标签体系（8 类）

破音/爆音音频削波失真，波形幅度超出量化范围
漏读合成遗漏部分输入文字
错读/多读多音字错误或合成多余内容
音色漂移同一句中音色出现明显变化
机械感/不自然韵律平淡、语调单一、听感机器化
语速异常明显过快或过慢
停顿不当句中停顿位置不符合语法或语感
无问题听感正常，无需标注

标签设计覆盖 TTS 常见缺陷的三大维度：语音质量（破音）、文本准确性（漏读/错读）、韵律自然度（机械感/语速/停顿）+ 音色稳定性（漂移）

5.2 技术实现：Gradio 6.x + CSV 持久化

前端：Gradio Blocks API

  • 选择 Gradio 而非 Flask/Django/FastAPI：Gradio 专为 ML/Audio 演示设计，内置 gr.Audio 组件（自动生成波形图 + HTML5 播放器），无需手写 Web Audio API 代码
  • 自定义布局：双列音频（参考 + 合成）+ 评分滑块 + 多选标签 + 备注文本框
  • server_name="0.0.0.0"：允许同一局域网内的其他设备（手机/平板）访问评测页面
  • 修复了 Gradio 6.x API 变更（gr.update() 已废弃，改为直接返回值）

后端：轻量 CSV 持久化

  • 无数据库依赖：评测结果即时追加写入 mos_results.csv
  • 支持断点续评：程序重启后从已有 CSV 条数推算进度
  • 每次提交自动记录：样本 ID + 两维 MOS + Bad Case 标签 + 备注

5.4 评测的局限性（诚实的工程反思）

  • 单一评测员：当前只有项目作者一人评测，结果参考价值有限。工业级 MOS 通常需要 20+ 评测员计算 95% 置信区间
  • Edge-TTS 天花板效应：10 句通用场景短文本全部满分，未体现 MOS 量表的区分能力。需要更难样本（数字/地址/专业术语）测试
  • 无 AB 盲测：评测员知道所有样本来自 Edge-TTS，可能存在期望偏差（expectation bias）
  • 改进路径：① 加入开源克隆模型（GPT-SoVITS）做对比，增加质量方差；② 实现 AB 盲测模式；③ 邀请多人独立评测并计算评分者间信度（Krippendorff's Alpha）
